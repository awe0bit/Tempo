# 扫码配对

当前 iOS 通过扫码连接自托管同步服务，不再手动填写地址或密钥。**二维码只从服务器生成，应用不提供生成入口。**

## 1. 在服务器生成二维码

先完成 [部署](DEPLOYMENT.md)，并更新到支持配对的服务版本。在运行同步服务的 Compose 目录执行：

~~~bash
docker compose exec sync /tempo-sync pair --server https://你的同步域名
~~~

把地址换成自己的 HTTPS 同步根地址，不要加接口路径。命令会在终端直接显示二维码和失效时间，不需要把同步密钥复制到命令中。

使用本仓库的 1Panel 编排时，可以在**主机终端**执行：

~~~bash
cd /opt/1panel/docker/compose/tempo-services
docker compose exec sync /tempo-sync pair --server https://你的同步域名
~~~

这里使用服务器终端直接运行容器内的程序，不要求容器有 shell，也不需要单独安装二维码工具。

## 2. 在应用中扫码

1. 安装支持扫码配对的 iOS 版本。
2. 打开“设置 → 自托管同步 → 扫码配对”。
3. 允许相机访问，对准终端中的二维码。
4. 核对服务器地址，点击“确认配对”。

连接验证通过后，应用保存配置并开始自动同步。原有本地任务不会因打开配对页面被清空；确认连接后，数据按同步规则与服务器合并。

## 二维码有效期

- 5 分钟内有效，只能使用一次。
- 每配对一台新设备，都在服务器重新生成二维码。
- 生成新码立即使上一张尚未使用的码失效；不会断开已经配对的设备。
- 服务重启会清除尚未使用的配对码，不影响已有连接或同步数据。
- 二维码不包含长期同步密钥，但有效期内仍能授权连接，请勿公开分享或上传截图。

## 换服务器与权限

更换服务器时使用“重新扫码配对”，确认后才替换原连接。扫码或验证失败不会覆盖之前保存的连接。

相机权限被拒绝时，可从提示进入系统设置开启，再重新扫码。应用不提供手动输入或粘贴密钥的备用入口。

旧安装包会提示更新；页面 OTA 本身不能增加原生扫描器或相机权限。

## 常见问题

| 提示或现象 | 处理方法 |
| --- | --- |
| 二维码已使用或过期 | 在服务器执行命令生成新码 |
| 服务器尚未支持配对 | 更新同步服务，再生成二维码 |
| 不是有效配对二维码 | 确认扫描的是上述命令生成的 Tempo 二维码 |
| 连接失败 | 检查公网 HTTPS、证书和网络；不要用仅容器内可访问的地址 |
| 终端二维码显示不完整 | 放宽终端窗口，并保留二维码四周的留白 |
| 想撤销某台已连接设备 | 当前仍使用共享同步密钥；更换服务器密钥后，所有设备都需要重新配对 |
